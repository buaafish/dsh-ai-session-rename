# 根据对话重命名会话

在侧边栏会话行的右键菜单里加一项 **根据对话重新命名**。点它之后，插件读取这个会话里你自己发过的消息，用这个会话**当前使用的模型**生成一个简短标题，并把它作为会话标题写回去。

## 用法

1. 在左侧会话列表里右键某个会话。
2. 选择「根据对话重新命名」（在「重命名」下面）。
3. 顶部会出现「正在根据对话生成标题…」的提示；成功后显示「已重命名为「…」」，失败则显示原因。

也可以在对话里直接让 agent 调用工具 `session_rename_ai`，它只作用于**当前会话**：
传入别的会话 id 会被拒绝，避免 agent 悄悄改掉你没在看的会话。

## 标题风格

- 中文 / 日文 / 韩文约 **8–14 字**，其它语言约 3–6 个词。
- 只要一行纯文本：不带引号、编号、Markdown、emoji、句尾标点。
- 描述具体话题或任务，不写「聊天」「对话」这类空词。
- 只用你自己输入的消息（`source.kind === 'user'`），注入的上下文和目标续轮不算；最多取最近 40 条，每条截断到 2000 字符。

## 用的是哪个模型

优先用**这个会话自己最后一次请求的路由**（`session.requestHeader().config`），所以你会话里选了什么模型就用什么模型；会话还没发过请求时退回全局默认模型。生成是一次独立调用（`maxTokens: 96`、温度 0.2、45 秒超时），不会混进会话历史。

## 一个取舍：标题会被「锁定」

DSH 里显式改标题的事件源是 `user`，而 `user` 源会让自动标题生成**不再调度**这个会话（`dsh-session-title/src/index.ts:519` 的 `if (this.get(session)?.source.kind === 'user') return`）。本插件复用了内置的重命名通路（`SessionFace.rename` → `session.title` 事件），因此：

- 好处是标题投影（侧边栏、标签页）会像手动重命名一样立刻更新，行为与官方「重命名」一致。
- 代价是这个会话之后不会再有自动标题，直到你再次显式改标题。

要「不锁定」只能自己 append 一条 `source: { kind: 'provider', … }` 的 `session/title` 事件绕过 `rename()`，但那样标题也会在下次 `refresh()` 时被 provider 覆盖，反而更不可控，所以没有采用。

## 两个入口，一份实现

- Host：`index.js` 的 `generateTitle()` 负责取消息、拼 prompt、调模型、解析输出。
- Host 路由 `POST /api/ai-session-rename`：给 UI 用，只**生成**标题，不写入。
- Host 工具 `session_rename_ai`：生成并写入调用方会话。
- Client：`client.js` 只负责菜单项、提示和调用 `SessionFace.rename`；标题逻辑不重复实现。

写入为什么不放在 Host：内置 `remote.session.rename` 已经会恢复冷会话、校验标题、更新投影，自己再写一遍只会多一条不一致的路径。

## 失败时你会看到什么

- 会话里还没有你发的消息 → 「还没有你的提问」。
- 会话没有记录模型路由、也没有默认模型 → 明确提示无可用路由。
- 模型返回空标题、只回工具调用、撞到输出上限、或超时 → 各自不同的原因。
- 会话在生成期间被关闭 → 「重命名失败，会话可能已被关闭」。

## 可调参数（`index.js` 顶部常量）

`MAX_MESSAGES` 40、`MAX_MESSAGE_CHARS` 2000、`MAX_INPUT_BYTES` 24000、`MAX_OUTPUT_TOKENS` 96、`TIMEOUT_MS` 45000、`MAX_TITLE_CHARS` 24。提示词在 `SYSTEM_PROMPT`，长度要求改这里即可。
